# 端到端优化补丁说明（2026-11-12）

交付日期：2026-11-13。稳定快照为 `release/2026-11-12-stable-before-e2e`（a0a7f391），开发位于 `main`，插件版本为0.2.0。源码和配置分别有独立fingerprint，便于从server日志确认部署版本和启动参数。

审查基线 a0a7f391。本补丁只修改外部 plugin，不直接编辑 vLLM / vllm-ascend 源码。启动命令、capture sizes、batch/token 限制和功能参数沿用现场原值；没有新增二分开关。目标是减少完整服务路径的额外成本，实际加速仍须由完整工作负载测量。

## 服务路径

- typed-SoA records：correction/decay 为 FP32；已归一化 key 保留输入 dtype，按 GQA key heads去重。checkpoint 更新仍按原 forward recurrence，不改为另一种数值次序。
- 纯 spec direct output：使用固定0.30rc1 native helper ABI完成相同卷积、gate和q/k norm，verify直接写最终core_attn_out；不再分配独立的core输出再copy。混合prefill、普通decode和无metadata profiling仍走原生分支；一旦卷积已提交，异常直接传播，不能重复执行fallback。
- 行映射与簿记：复用原生行映射和持久缓冲，不重复阻塞H2D；按step收集group-owned metadata，固定长度plan决定有效行与align列。
- 多组提交：各层保留自己的group/block/stride/record归属，将兼容组的plan、conv和fold统一提交；不能假设三组的物理block ID一致。
- sampling filter：原来的概率阈值逻辑按行分块，限制临时活跃张量；有经过启动探针验证的值排序接口时不产生无用INT64索引。随机采样与拒绝采样顺序不变。
- 诊断：在现有CPU完成输出上统计真实token、接受长度和图padding，分别记录Host提交时间；没有设备计时混称。

## Triton-Ascend 3.2.2 参数合同

kernel运行时参数采用Tensor/标量flat ABI，tuple只用于内核内部静态索引和constexpr。每个物理提交桶最多三组，更多组自动分桶；启动期持久描述表负责跨桶统一发布align，不增加每步指针上传。当前Qwen三组对应三次kernel提交；异构布局或更多组会明确记录实际提交数。

## 启动和图生命周期

startup以compile-only准备真实页数/record几何、activation布局的verify签名，以及align/none可选输入、映射dtype和record行域对应的commit；不执行完整模型dummy forward。graph-padding plan容量与真实record行数区分。所有需要的context在ready前绑定，实际record bytes超过预留则拒绝ready。

已有的正常run_fullgraph首次执行保留，以完成native task update和external-event依赖。capture metadata只在capture窗口保留，用后释放；服务期eager不再强持metadata。没有任意运行时图异常后的自动重试，以避免重复部分state写。

自检在feature开启时自动执行，包含Q全部接受长度、GQA输出、null/padding/align及conv，结果失败则拒绝ready。自检使用自有buffer并恢复随机数状态。512MiB现有transient headroom默认值保留，不把它当作records或实际graph pool的测量。
